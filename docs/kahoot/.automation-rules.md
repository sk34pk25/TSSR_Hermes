# Règles d'automatisation Kahoot

## Principe fondamental

> **Un module réel = un Kahoot associé**

Le Kahoot est généré à partir du contenu pédagogique réellement enseigné.

## Règles

1. **Nombre de questions**
   - Maximum absolu : **20 questions** par Kahoot.
   - Le nombre réel dépend de la densité du module :
     - Module très court → 5 à 8 questions si cela suffit.
     - Module moyen → environ 8 à 15.
     - Module dense → jusqu'à 20.

2. **Cohérence**
   - Une modification significative du module doit déclencher une vérification de cohérence du Kahoot.
   - Ne jamais créer un deuxième Kahoot distant si le module possède déjà un Kahoot synchronisé : mettre à jour l'existant lorsque le MCP le permet.

3. **Qualité avant quantité**
   - La qualité et la pertinence passent avant le nombre.
   - Ne jamais forcer un quota de questions.

4. **Source des questions**
   - Une question évaluée doit être basée sur une information réellement enseignée dans le module.
   - Ne jamais inventer une information absente du cours.

5. **Sécurité**
   - Aucun credential ni token dans Git.
   - Ne jamais supprimer un Kahoot existant sans nécessité.
   - Ne toucher qu'aux Kahoots du projet de démonstration.

## Pipeline automatique (futur)

```
Support de cours → analyse → résumé pédagogique
  → Cours → Module → notions importantes
  → Révision → Exercices
  → génération du Kahoot
  → création/mise à jour via MCP Kahoot
  → lien du Kahoot dans TSSR NEO+
```
